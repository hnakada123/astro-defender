カプセルと連結ビーム砲

時間制限のある強化と、シールド・連結砲のような回数で管理する効果を分けます。

主な参照先：PU_DEFS / maybeDrop / applyPU / active / BEAM_OFFSETS / BEAM_LOSS / SPARE_BONUS

4種類の効果をデータで定義する

カプセル状態の持ち方効果
Wactive.wide に残り秒数8秒間、3方向へ射撃
Ractive.rapid に残り秒数8秒間、射撃間隔を短縮
Sactive.shield に有無ダメージを1回防ぐ
Bactive.beam に砲の数1回の取得で1門ずつ左右交互に増加、最大4門。ビームは1門につき画面内1発まで。ミスで2門減る

落とす、拾う

通常の敵の撃破時に、約8%の確率でカプセルを作ります。同時に存在できるのは2個までです。カプセルは毎秒62 pxで落下し、自機より少し大きい回収用の四角形と重なると applyPU() が効果を反映します。

カプセルを自機へ引き寄せる処理はないので、拾うには落ちてくる位置へ自機を動かします。地面の高さ GROUND_Y を越えたカプセルは消えます。回収できるのは自機が生存している間だけです。ループの途中で splice により要素を取り除くため、配列の末尾から先頭へ向かって回しています。

連結砲は時間で消えない

Bカプセルは1個につき連結砲を1門追加し、d.max、つまり BEAM_OFFSETS.length の4門で止めます。取るたびに「BEAM LINK ×3!」のように現在の門数を表示します。門数が増えると外側の砲まで画面内に収める必要があるため、clampPlayerX() で自機の位置を補正し直します。

シールドがあるときのS、4門そろった後のBは、取っても効果が増えません。拾い損にならないよう、代わりに SPARE_BONUS の500点を加え、「SHIELD +500」「BEAM LINK MAX! +500」と表示します。

砲の位置は BEAM_OFFSETS の先頭から順に使います。1門目は左 (-24)、2門目は右 (+24)、3門目はさらに外側の左 (-42)、4門目は右 (+42) なので、取るたびに左右交互に増えていきます。各砲は通常ショットと同じタイミングで縦長の弾を1発ずつ撃ちます。この弾は敵に当たると消える普通の弾で、貫通はしません。

ビームは通常弾の同時発射数の上限には数えません。そのかわり、1門につき画面内に1発までです。発射前に pBullets を1回だけ見て、通常弾の数と、ビームが飛んでいる砲の番号 (slot) をビット (beamSlots) に記録します。ビットが立っている砲は、前の弾が敵に当たるか画面の外へ出るまで撃ちません。近くの敵ほど弾がすぐ消えるので連射が速くなり、4門そろっても火力が際限なく増えることはありません。

連結砲はW・R・Sと併用でき、次のウェーブにも持ち越せます。シールドで防げなかったミスでは BEAM_LOSS の2門だけを失い、残りは復帰後もそのまま使えます。4門なら2門に、1門なら0門になります。シールドが攻撃を防いだ場合は1門も失いません。

読み解くポイント

active は取得中の効果をまとめたオブジェクトです。W・Rは残り秒数、Sは有無、Bは門数と、キーごとに値の意味が違います。秒数は updatePlay() で毎フレーム減らし、0になれば効果が切れます。連結砲は門数を数値で持つので、「1門増やす」「2門減らす」をそれぞれ足し算と引き算1つで書けます。

確かめてみよう

Bカプセルを5回取得したときの active.beam を追い、1 → 2 → 3 → 4 → 4 になることを確認してください。続けてミスしたときは Math.max(0, active.beam - BEAM_LOSS) で2に、1門のときのミスでは0で止まることも確かめてください。
