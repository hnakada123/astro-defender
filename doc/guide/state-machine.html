画面と状態遷移

タイトル、プレイ、ミス、クリア、ゲームオーバーを状態で管理します。

主な参照先：state / stateT / setState / setPaused

画面名を1つの変数で表す

状態起きること次の状態
title開始入力を待つstartGame() で play
play移動・射撃・衝突を処理被弾で dying、全滅で clear、侵入で gameover
dyingミスの演出を待つ1.15秒を超えると残機に応じて復帰か終了
clearクリア演出を表示1.6秒を超えると次のウェーブを作って play
gameover結果を表示0.6秒を超えてから開始入力で再挑戦

状態の切り替えと経過時間

stateT は現在の状態になってからの秒数です。切り替えるたびに0へ戻すことで、「ミスしてから何秒待つか」をその状態だけの条件として書けます。updateCommon() は星やパーティクルなどの共通処理、updatePlay() は戦闘専用の処理です。clear では入力を待たず、1.6秒を超えたフレームで wave++・makeWave()・setState("play") を続けて実行し、次のウェーブを始めます（ウェーブクリアと次のウェーブ）。dying からプレイに戻る時は、ミスした時に hitPlayer() が止めた円盤の効果音を、円盤がまだ画面にいれば鳴らし直します。

ポーズは別のフラグ

paused は state と独立しています。プレイ中またはミスの演出中に一時停止しても、どちらの状態だったかは失われません。setPaused(true) は押しっぱなしの入力を解放し、音の予約を止めます。

読み解くポイント

画面の描き分けとルールの進行は別です。クリア表示中も星やパーティクルは動きますが、state === "play" ではないため戦闘は進みません。

確かめてみよう

setState( を検索し、それぞれがどの条件で呼ばれるかを見てください。残機が0になる瞬間と、ゲームオーバー画面へ移る瞬間の違いが分かります。
